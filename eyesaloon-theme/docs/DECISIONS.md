## 2026-08-07 - Virtual try-on uses open-source stack with QR mobile handoff

- Options considered: pay for a Shopify virtual try-on plugin, build a custom app with open-source browser libraries, or postpone try-on until after launch.
- Choice: keep virtual try-on in the custom `eyesaloon-tryon` app/theme app extension and use open-source libraries only: MediaPipe Tasks Vision for face tracking, Three.js for GLB rendering, and an open-source QR generator for desktop-to-mobile handoff.

- Constraint: normal product pages must stay fast. The try-on block renders only a lightweight button/modal shell, then lazy-loads QR, camera, landmark, and 3D code after customer intent.

## 2026-08-05 - Homepage hero rebuilt as `eyesaloon-hero-carousel` per design handoff

- Options considered: extend the existing single-slide `eyesaloon-hero` section with a slides array, or replace it with a new dedicated carousel section.

- Corrected two invalid-Liquid patterns present in the naive port from the HTML/JS prototype (caught by `shopify theme check`): Liquid has no `ternary` filter (used explicit `if/assign` for the `loading` attribute instead), and `{% for x in a, b, c %}` is not valid Shopify Liquid tag syntax (replaced with three explicit `{% if %}` blocks for the trust-row items).

## 2026-08-05 - Fixed: large category tile rendered much taller than the small-tile stack

- Symptom (reported by Zee after the previous fix landed): on desktop, the blue "Prescription frames" tile was visibly much taller than the 3 stacked small tiles beside it, instead of the two columns matching height.
- Root cause: `.eyesaloon-category-tile { min-height: 34rem; }` applied to every tile, large and small alike. With 3 small tiles stacked (this build has 4 tiles total, not the mockup's 3), the stack's natural height became `3 × 34rem + 2 × 2rem gap ≈ 106rem`. The large tile used CSS Grid's `grid-row: span 2` to visually match a *2-row* implicit grid — a technique copied from the static prototype, which only ever had exactly 2 small tiles. With 3 small tiles the row-matching math no longer held, and the grid's auto row-sizing stretched the spanned large tile to match the now much taller stack.
- Fix: replaced the top-level `display: grid` + implicit-row-span trick with `display: flex` on `.eyesaloon-category-tiles__grid` (`align-items: stretch`, large tile `flex: 1.4 1 0`, `.eyesaloon-category-tiles__stack` `flex: 1 1 0`), and made small tiles `flex: 1 1 0` inside the stack so they split whatever height the row ends up at. Flexbox's cross-axis stretch equalizes the two columns to the taller of the two natural heights, however many small tiles exist — this is robust to the block-count changing (unlike the grid-row-span trick, which only worked for exactly 2 small tiles), which matters here since the schema explicitly allows Zee to add/remove tiles from the editor.
- Reduced the shared `.eyesaloon-category-tile` `min-height` from `34rem` to `15rem` (a sane floor, not a driver of layout) and gave the large tile its own `min-height: 34rem` so a lone/short stack doesn't shrink it below a reasonable size.
- Updated the 900px/560px responsive rules to match: below 900px the grid switches to `flex-direction: column` (large tile at a fixed `28rem`, stack tiles wrap 2-per-row at `flex-basis: calc(50% - 1rem)`), below 560px the stack drops to a single column.
- Verified with real box measurements via `shopify theme dev` + injected JS (`getBoundingClientRect()`), not just a visual screenshot: at 1400px viewport, large tile and stack both measured exactly 490px; at 721px (the 900px breakpoint's mobile branch), large tile 280px and stack tiles 200px each, matching the explicit mobile values.

## 2026-08-05 - Fixed: small category tile titles clipped at the top edge ("touching the roof")

- Symptom (reported by Zee, screenshot of the live preview): in the small-tile stack, each title sat right at the tile's top edge with no visible top padding, while extra empty space collected at the bottom instead.
- Root cause: the previous fix's `flex: 1 1 0` (flex-basis `0`) on `.eyesaloon-category-tile` let the browser's flex-grow algorithm divide the stack's height equally across all 3 small tiles *without regard for each tile's own content size* — measured directly via `getBoundingClientRect()`, each tile was compressed to 150px while its own padding (40px + 40px) plus content (~95px) needed 175px. With `justify-content: flex-end` and `overflow: hidden`, the 25px shortfall meant the content block overflowed past the tile's top edge and got clipped there — not a padding bug, a sizing bug that happened to look like a missing top padding.
- Fix: changed `flex-basis` from `0` to `auto` on both `.eyesaloon-category-tile` and `.eyesaloon-category-tiles__stack` (`flex: 1 1 auto`) so each tile's minimum size always respects its own content + padding first, and `flex-grow` only distributes genuine surplus space (e.g. to match the large tile's height) on top of that floor — it can no longer compress a tile below what its own content needs. Also trimmed small-tile padding from `4rem` to `3.2rem` (kept `4rem` only on `.eyesaloon-category-tile--large`) for a more proportionate compact-card feel.
- Verified with the same `getBoundingClientRect()` technique as the previous fix, not just a screenshot: all 3 small tiles now measure 32px between the tile's top edge and the title's top edge (matching the 3.2rem/32px padding exactly), all 3 are equal height (181px), and the large tile still stretches to match the stack's total height precisely (584px both) — confirming the height-matching behavior from the prior fix survived this change.
- Takeaway carried forward: `flex-basis: 0` is only safe when every flex sibling's content is known to fit within its share of the container; whenever content length can vary (translations, merchant-edited text, variable block counts) prefer `flex-basis: auto` so the browser's built-in "never shrink below content" protection stays active.
